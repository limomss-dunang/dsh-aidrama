# 功能与流程审查（按调研项目对照）

日期：2026-11-05
审查依据：`docs/04-审查清单.md`、`research/notes/01-05`、当前 `src/` 代码。

## 结论

这次不再按“字段是否齐全”审，而按四层审：

1. 功能是否该存在；
2. 职责是否放对；
3. 实现是否正确；
4. 结果是否可验收。

已确认并修正的高风险项：

- **删除用户可见的“剧本理解”确认页**。调研项目没有把“角色性别/服装”作为用户确认步骤；这是解析器职责。
- **剧本事实解析改为内部自动**：角色生成/场景生成前，自动用 LLM 从剧本人物候选里抽取性别、服装、原句证据；解析失败就停止生成资产，不把“未知”丢给用户。
- **角色生成硬校验**：名字必须来自剧本人物表；性别与解析结果冲突时拒绝；剧本没有“囚服/狱服”却生成囚服/狱服时拒绝。
- **移除解析确认门禁**：不再要求用户点确认才能生成。
- **保留结构门禁**：主要角色缺失（GEN-018）、本集场景缺失（GEN-019）。

## 明确不再做/不建议做

1. **不再做“剧本理解”用户确认页**：没有调研先例，且把解析失败转嫁给用户。
2. **不允许“未知性别”作为最终角色属性**：解析器必须给主要角色性别；判断不了就报解析失败，不进入资产。
3. **不允许按身份猜服装**：身份是“钦犯”不等于“囚服”；只认剧本明写，未写明用中性默认并标注。
4. **不在文本/资产未验收前自动生图/视频**：调研项目都有阶段门；这次真实测试已经证明跳过门的代价。
5. **不把 0 error 当内容通过**：结构校验只做第四层；内容对照必须单独做。
