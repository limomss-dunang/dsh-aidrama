# 插件设计：dsh-aidrama

> 状态：v0.2 已实现并在本机 DSH profile 安装；覆盖剧本导入、Seedream 图片、MiMo 音色、Seedance 2.0 对白视频、LOOK 造型切换、自动时长与项目目录迁移。
> 配套：[00-调研报告.md](00-调研报告.md)、[02-TTS与模型配置调研.md](02-TTS与模型配置调研.md)、[../README.md](../README.md)、[../research/notes/](../research/notes/)。

## 1. 目标与非目标

**目标**：把 AI 短剧/漫剧的「构想 → 总纲 → 资产 → 分集 → 分镜 → 提示词 → 生产台账 → 质检」做成一个 **侧边栏工作台里的结构化制片台**：

- 机器可校验的状态（不是一堆散落提示词）；
- 模型方言编译器（选错方言会真的写错任务类型）；
- 人和 Agent 共编（Agent 有两个工具，UI 与工具读写同一份 project.json）；
- 数据落在 workspace 或用户选定目录，可导出五份 Markdown 交接给外部 skill；
- 从资产参考图到对白视频的轻量生产链路：Seedream 生图 → MiMo 音色样音 → Seedance 2.0 对白视频。

**非目标**：不做 NLE、不做投流、不做多租户、不替代 DSH 的 Agent/审批/会话；不做逐句 TTS 时间线与混音（当前走视频模型原生对白）。

## 2. 形态

与 `dsh-imagegen` / `dsh-video-replica` 一致：**侧边栏入口 + 中栏工作台接管**，不注册 `conversation.view`，不占用会话头部的 View 标签。

- 侧边栏在「新会话」旁插入「会话 / 短剧」两个按钮；已有生图 tab 容器时并入其中。
- 点「短剧」后：`<html data-aidrama-active>` → 中栏隐藏原生会话子树、显示 `[data-aidrama-view]`；点「会话」或会话列表行切回。
- 与其它面板互斥：派发 `dsh-panel-activate` 事件，并移除 `data-dvr-active` / `data-dsh-imagegen-active` 等属性；别的面板打开时自动关闭。
- 当前 sessionId 从 `[data-conversation-content][data-conversation-session]` 读取，再调 `/api/dsh-aidrama/session` 解析 workspace cwd；没有会话时显示空状态。
- 会话子树保持挂载，切回后 Chat 状态不丢。

早期版本曾注册官方 `conversation.view`（研究阶段验证过 `aidrama` occupant 可注册）；按用户要求改为与生图/视频复刻一致的侧边栏形态，View 注册已移除。

## 3. 信息架构

```
短剧工坊（侧边栏「短剧」+ 中栏工作台）
├── 顶栏：品牌 / 项目切换 / 新建 / 导入剧本 / 删除 / 校验 / 导出 / 保存 / 设置
├── 左栏：制片流程（阶段导航 + 计数 + 制片进度）
│   ├── 构想 Concept
│   ├── 总纲 Bible
│   ├── 资产 Assets（角色 / 场景 / 道具 / 风格锚）
│   ├── 分集 Episodes（节拍 + 剧本 + 自动时长）
│   ├── 分镜 Storyboard（表 + 卡 + 造型 LOOK）
│   ├── 提示词 Prompts（自动方言 + 编译 + 警告）
│   ├── 生产 Production（任务单 + 台账）
│   └── 质检 QC（findings + 导出）
├── 中栏：当前阶段内容（最大宽度 1100，卡片化）
├── 右栏：检查器（角色九槽 / 三视图 / LOOK / 音色 / 镜头 / 场景 / 道具 / 风格）+ 校验摘要 + 下一步
└── 设置弹窗：文本 / 图片 / 视频 / 配音 / 项目 五个标签
```

UI 采用与 `dsh-video-replica` 一致的「品牌头 + 左流程轨道 + 中舞台 + 右详情」骨架；所有表面色用 `color-mix(currentColor …)`，不依赖可能在深色主题解析成白色的 brand token。没有照搬 LocalMiniDrama 的节点画布，因为本插件的强项是线性门禁与可校验状态。

## 4. 数据模型

`<workspace>/.dsh-aidrama/projects/<projectId>/project.json`，`schema: "dsh-aidrama/v1"`。

```
Project
├── meta: platform / orientation / genre / targetEpisodes / episodeSeconds / durationMode
│        audience / logline / theme / hook / forbidden[] / dialect
├── bible: premise / world / arc / episodePlan / visualDirection
├── characters[]: id / name / role / status(draft|locked) / slots(9) / lockText / identityLock
│                 looks[]{id,text,episodes,refs{},refPrompts{}} / stateVariants[]
│                 refs{front,side,back,expression,main} / refPrompts{} / voiceCard
├── scenes[]: id / name / space / props / palette / keyLight / refImage / variants[]
├── props[]: id / name / function(5) / appearance / owner / endPosition / refImage
├── styles[]: id / name / prompt / avoid[]
├── episodes[]: id / title / logline / status / targetSeconds / beats[] / script / shots[]
│   └── shots[]: id / sceneId / duration / size / camera / blocking / action / endState
│                emotion{start,trigger,end} / dialogue[] / sound{} / refs[] / wardrobe{}
│                locks[] / status / videoPath / prompt{dialect,text,compiledAt,version,inputHash,warnings[]}
├── scriptAnalysis: episodes[]{episodeId,cast[]{name,gender,evidence,costume,costumeEvidence},locations[]} / accepted / generatedAt
├── decisions[]: id / field / status(proposed|accepted) / value / at
├── jobs[]: id / kind(image|video|tts|music) / shotId / status / providerTaskId / costCny / startedAt / endedAt / note
└── ledger[]: at / shotId / event / detail / costCny
```

关键取舍：

- **结构是机器真相，Markdown 是交付皮**。导出生成 `project.json` + 五份 md；不从 md 反向解析（避免两套真相）。
- **身份锁与造型分离**：`identityLock` 保存脸/发型/体型/气质/禁改项；`looks` 保存服装/配饰/妆造。编译时按镜头 `wardrobe` 选 LOOK，再拼成有效锁面。
- **参考图四态**：`ref / plan / missing / t2v`，与 drama-skills 的 REF/PLAN/待补/文生对齐；`missing` 阻断投产。
- **提示词带版本 + 输入指纹**：`prompt.version` 为 0 的旧编译自动重编译；`prompt.inputHash` 与当前分镜/身份/LOOK/场景不一致时，validator 报 GEN-017，视频生成前强制重编译。
- **状态单一**：每镜一个 `status`；校验/导出/UI 都是投影，不另存状态。
- **时长可固定可自动**：`meta.durationMode=fixed|auto`；`episode.targetSeconds` 为 0 时用项目单集时长，auto 模式按分镜/剧本回填每集目标。

## 5. 流水线与门禁

| 阶段 | 准入 | 门禁 |
|---|---|---|
| 构想 | 一句话 + 平台 + 时长 + 题材 + 受众 + 禁区 | logline 非空；平台时长合法 |
| 总纲 | 构想 | premise/world/arc/episodePlan/visualDirection 非空 |
| 资产 | 总纲/剧本 | ID 唯一；角色九槽；参考槽位要么有文件、要么显式 plan；锁面可渲染 |
| 分集 | 资产 | beats 秒数合计 = 本集目标（±2s）；auto 模式按分镜/剧本回填 targetSeconds |
| 分镜 | 分集 | 一镜一主动作；台词容量；场景引用存在；参考四态自洽；wardrobe 引用的 LOOK 存在 |
| 提示词 | 分镜 | 方言自动跟随视频模型；身份锁/LOOK 逐字进正文；时间戳/H3 互斥/矛盾约束 |
| 生产 | 提示词 | 任务单 + 台账；生成前检查参考图/音色/提示词；图片/视频落盘并登记 job/ledger |
| 质检 | 生产 | findings 分级；导出前 error 必须清零（人可确认后导出） |

**生成前置检查**（客户端 + 宿主双重）：
- 总纲：构想的一句话/主题；
- 角色/场景：总纲的故事前提；
- 生成本集节拍：总纲前提 + 一句话 + ≥1 角色 + ≥1 场景；
- 生成分镜：本集剧本或节拍 + ≥1 角色 + ≥1 场景。
缺项时按钮禁用并在面板/Toast 显示缺什么，宿主直接拒绝。

### 5.1 剧本导入

入口：新建项目弹窗 + 已有项目的「导入剧本」。

- 输入：TXT / Markdown / DOCX（宿主解 zip 读 `word/document.xml`）/ 直接粘贴；DOCX 由浏览器转 base64，宿主用 `node:zlib` 解压，不引第三方包。
- 拆集：先在客户端/宿主按「第X集 / EP01 / Episode N」标题确定性切分，正文原样保留；模型只提取元信息、角色、场景、道具、每集节拍与一句话，不改写正文。
- 深度：资产 + 全部集剧本；**只第一集**自动生成分镜并编译提示词，其余集由用户逐集生成，避免一次导入烧掉大量 token。
- 预览：解析结果先成 draft，展示数量、error/warn、token；可改剧名/一句话/单集时长/题材/平台、角色名与定位、分集标题与一句话；确认后才落盘。
- 缺失信息：能确定的才填；平台/时长/集数不确定就留空或保留默认，不编造。
- 模型：设置里的「剧本解析专用模型」优先，空则回退文本模型；分镜仍走文本模型。
- 合并：已有项目只补空字段、按 ID 合并资产、按集 ID 更新剧本正文，保留已有分镜与手改内容。
- 节拍兜底：解析模型若把 beats 的 seconds 全给 0，导入时按单集目标均分，避免一次导入产生一批 GEN-005。

### 5.1.1 剧本事实解析（内部）

资产生成前内部解析每集正文，产出 `scriptAnalysis`：

- 人物名、场景标题和原句依据；
- 只记录文字能证明的性别/服装；剧本未写服装就标“未明写”，**不按身份猜囚服**；
- 该结果是生成器的输入约束，不是用户确认步骤，也不新增「剧本理解」按钮；
- 角色生成只允许使用剧本人物表里的名字；性别/场景与已解析事实冲突时拒绝落盘。

### 5.2 Seedream 图片 + MiMo 音色 + Seedance 2.0 对白视频 + LOOK 造型

- 角色造型：`Character.looks[]` 每个 LOOK 有独立的 `text / episodes / refs / refPrompts`；角色面板可添加/删除 LOOK，改描述与提示词后「抽正视 / 抽侧视 / 抽背视 / 抽三视图」各自重抽。
- 身份与服装分离：`identityLock` 只写脸/发型/体型/气质/禁改项；LOOK 写服装/配饰/妆造。编译时按镜头 `shot.wardrobe[characterId]` 选 LOOK，拼成「身份锁 + 造型（LOOK-xx）」。
- 默认 LOOK：角色没有 LOOK 时用 `slots.outfit + accessories` 生成合成 LOOK-01，不强制写数据。
- 基础参考图：`character.refs` 保留为无 LOOK 时兜底；LOOK 参考图优先用于分镜/视频。
- 场景/道具：Seedream 生成 `refs/scene-<id>.png` / `refs/prop-<id>.png`，提示词可改、可重抽。
- 分镜首帧：可用 Seedream 生成，也可手动上传；写入 `role: first` 参考槽。
- 角色面板：音色描述 + 试音文本 → `mimo-v2.5-tts-voicedesign` 生成 `audio/voice-<角色>.wav`。voicedesign 不返回 voiceId，所以项目存的是样音文件，不是音色 ID；改描述后点「重抽音色」会覆盖当前样音。
- 分镜面板：上传/生成首帧后点「生成对白视频」。
- 视频请求：Seedance 2.0 多模态参考，`reference_image` + `reference_audio`（说话角色样音）+ 提示词里的对白，`generate_audio: true`；输出 `videos/<shotId>.mp4`。
- 提示词版本：编译结果写 `prompt.version=1`；旧版本/方言不一致/空提示词在生成视频前自动重编译，确保 LOOK 和方言没有滞后。
- 限制：Seedance 2.0 带参考音频时至少一张参考图；参考图含真人人脸可能被方舟拒绝；台词准确率/音色一致性由视频模型决定，改词要重生成整镜。

### 5.3 LOOK 造型切换

- **保持**：同一角色的镜头都绑同一个 LOOK；只改这个 LOOK 的描述/参考图，所有绑定它的镜头一起更新。
- **换装**：新建 `LOOK-02`，抽好该 LOOK 的参考图；在换装点的镜头把 `wardrobe[characterId]` 切到 `LOOK-02`，之后镜头继续绑新 LOOK；前面镜头保持 `LOOK-01`。
- 校验 `GEN-016`：wardrobe 引用不存在的角色/LOOK → error；LOOK 没有参考图 → warn。
- 旧项目没有 LOOK 时默认合成 LOOK-01；要使用多套造型需手动添加。
- `stateVariants`（淋雨/受伤/变老）仍是记录字段，尚未像 LOOK 一样进入编译；当前只解决服装/配饰切换。

## 6. 生成器

`Generator` 把「项目摘要 + 当前阶段 + 用户补充要求」交给 DSH 已配置模型，要求严格 JSON。

阶段：`bible / characters / scenes / props / episode / shots`。

**分镜分段生成**：一集 10+ 镜的完整 JSON 很容易撞上模型输出上限被截断（实测在 5783 字符处断在属性名中间）。因此按每段最多 5 镜、独立调用：

1. 按 `episodeSeconds/4` 估最大镜数（4–14）；
2. 每段要求 `duration` 合计约等于该段应分摊的秒数；
3. 每段独立 `maxTokens: 3600`，失败只影响该段；
4. 合并后统一编号，检查 `sceneId` 是否存在，不存在回退到第一个场景并写入 notes；
5. 最后把时长差逐镜补齐到本集目标（每镜 4–15 秒，与视频模型门禁一致）。

**JSON 健壮性**：`chatJson` 容忍围栏/解释；截断或解析失败时第二次提高 maxTokens、要求压缩字段并完整闭合；仍失败抛出带原文截断的错误。

## 7. 方言编译器

`compileShot(project, episode, shot, dialect)` → `{ text, warnings }`；`compileShotInto` 写回 `shot.prompt` 并置 `version=1`。

方言由视频模型自动推导（`dialectForVideoModel`），不再单独设置：

| 视频模型 | 自动方言 |
|---|---|
| `doubao-seedance-2-0-*` | `seedance-2.0` |
| `doubao-seedance-2-5*` | `seedance-2.5` |
| `MiniMax H3` | `minimax-h3` |
| `Kling` | `kling` |
| `Wan 3.0` | `wan-3.0` |
| 未识别/空 | 回退项目 `meta.dialect` 或通用 |

支持：

| 方言 | 结构 | 硬规则 |
|---|---|---|
| `generic` | 中文五段式（画面/表演/对白/声音/运镜/锁/参考/负面） | 锁面逐字；负面约束 |
| `seedance-2.0` | `参考 @图片N…` + `镜头 1/2` | 不硬塞秒数；素材职责 |
| `seedance-2.5` | `镜头 1 [0:00–0:0X]` + `{角色说：}` + `<声音>` | 时间戳连续；任务类型 reference；禁字幕句 |
| `minimax-h3` | 三段（Base/首帧/首尾帧）或六段（full-reference） | 首尾帧与参考互斥；无配乐写 `N/A`；`<d>[Chinese]` |
| `kling` | 写法级模板 | 标「实验」，不宣称协议级 |
| `wan-3.0` | 写法级模板 | 标「实验」，不宣称协议级 |

方言的版本/来源应做成数据文件（后续），当前以常量 + 文案提示「以官方当前文档为准」。

编译时的有效锁面：

```
身份锁（identityLock 或九槽去掉服装/配饰）
+ 造型（LOOK-xx）：当前镜头 wardrobe 选中的 LOOK 描述
```

`GEN-007` 在 `prompt.version>=1` 时检查身份锁与 LOOK 文本都逐字进入正文；旧版本提示词跳过检查，生成视频前自动重编译。

## 8. 校验器

`validateProject(project, episodeId?)` → `{ findings, errors, warns, checkedAt }`。

已实现规则：

| rule_id | 级别 | 判据 |
|---|---|---|
| GEN-001 | error | 角色/场景/道具/分镜 ID 唯一且非空 |
| GEN-002 | error | 分镜的 sceneId / 台词说话人 / 锁引用存在 |
| GEN-003 | error/warn | 缺主动作；4 个以上动词启发式提醒一镜多动作 |
| GEN-004 | error | 台词字数/3.8 ≤ 时长−0.5；舞台指示/纯省略号不可朗读 |
| GEN-005 | error/warn | beats 秒数合计 = 本集 targetSeconds（±2s）；分镜合计 warn |
| GEN-006 | error/warn | 参考图四态；同一路径不能占多槽 |
| GEN-007 | error | `prompt.version>=1` 时身份锁与 LOOK 文本必须逐字出现在编译正文 |
| GEN-008 | error | Seedance 2.5 时间戳连续、总和=时长 |
| GEN-009 | error | H3 首尾帧与参考被拆成两段 |
| GEN-010 | warn | 矛盾约束（胶片+4K、慢动作+高速、电影感+纪实手持） |
| GEN-011 | warn/info | 单句 >20 / >15 字 |
| GEN-012 | warn | 左右站位 + 跳轴 |
| GEN-014 | info | 首帧参考 + 过程性动作 |
| GEN-016 | error/warn | wardrobe 引用不存在的角色/LOOK；LOOK 无参考图 |
| GEN-017 | warn | `prompt.inputHash` 与当前输入不一致，提示词已过期 |
| GEN-018 | error/info | 剧本主要角色不在角色表（前 4 个按频次硬要求，其余 info） |
| GEN-019 | error | 本集剧本场景没有对应场景资产 |
| COST-001 | warn | 单镜图片任务 >5 次 |

规则分级的意义：只有 `error` 阻断；`warn` 允许人确认；`info` 不判错。避免「用统一配方压创作」。

| `/api/dsh-aidrama/voice-design` | POST | MiMo 生成角色音色样音 |
| `/api/dsh-aidrama/image-generate` | POST | Seedream 生成角色/LOOK/场景/道具/首帧 |
| `/api/dsh-aidrama/shot-image` | POST | 上传分镜首帧 |
| `/api/dsh-aidrama/video-generate` | POST | Seedance 2.0 生成对白视频 |
| `/api/dsh-aidrama/asset` | GET | 播放项目内音频/视频/图片（支持 Range） |

所有路由只接受本机 loopback + 同源；项目目录路径由 `cwd` + 项目 id 构造，id 白名单正则；写入用 temp→rename 原子替换 + revision 乐观锁。

## 10. Agent 工具

| 工具 | 作用 |
|---|---|
| `aidrama_status` | 读取当前会话绑定项目的摘要、阶段、校验 error、下一步；不改文件 |
| `aidrama_generate` | 生成某阶段并保存；返回 notes + token + 校验计数 |

工具通过 `exec.agent.id`（即 sessionId）解析会话绑定，不需要模型知道 cwd。未绑定时返回明确引导：「先在侧边栏『短剧』工作台里新建或打开一个项目」。

## 11. 存储与安全

- 配置：`~/.dsh/storages/dsh-aidrama/config.json`（模型选择、会话绑定、手动接口的 Key）。Key 明文存本机，不进入项目文件。
- 项目：默认 `<workspace>/.dsh-aidrama/projects/<id>/project.json` + `exports/`；新建项目时可选目录，项目建在 `<所选目录>/<id>/`。设置里显示「当前项目文件目录」和「项目根目录」；更改根目录会移动该目录下的全部项目（项目 ID 不变）。导入新项目不允许静默切全局根目录。
- 并发：`ProjectStore.save` 以真实项目目录（realpath）为锁键，锁内读磁盘 revision 做 CAS；所有项目写使用唯一临时名。冲突时不覆盖磁盘，客户端保留本地草稿。
- 媒体：视频提交前先落 pending job，拿到 provider taskId 后立即回写 running；失败落 failed。当前仍不做重启恢复/只重下载。
- 方言：提示词方言由视频模型自动推导（`dialectForVideoModel`），不再单独设置；编译时写回 `project.meta.dialect`。
- 导出：`<项目目录>/exports/`。
- 文本生成走 DSH `llm` 服务（消息 content 必须是 block 数组，不能是裸字符串）。
- 图片/视频/TTS 走手动接口（Seedream、Seedance 2.0、MiMo voicedesign）；凭据只存本机配置。
- 客户端任何 DOM/挂载错误只告警，不阻断 Web 启动；工作台容器独立，出错不影响会话子树。

## 13. 已知限制

- 分镜生成仍可能因模型输出上限分段失败；已分段，但弱模型可能每段都超。
- 自动时长是估算：有分镜用分镜时长和，没有分镜用剧本字数/节拍文字粗估；不是精确成片时长，改完内容需再点「按内容回填」。
- `stateVariants`（淋雨/受伤/变老）尚未接进编译；当前只支持 LOOK 服装/配饰切换。
- 方言是常量而非带日期的数据文件；`verifiedAt` 显示在 UI 尚未实现。
- Seedance 2.0 带参考音频时至少需要一张参考图；参考图含真人人脸可能被方舟拒绝；对白准确率/跨镜音色由视频模型决定，改词需重生成整镜。
- Seedream/Seedance/MiMo 都是手动接口；Key 明文存本机配置，未做托管或加密。
- 项目目录是「一个根目录 + 多项目」模型，移动会搬全部项目；不支持每个项目独立根。
- revision CAS 与临时文件锁是单进程内；多 DSH 实例同时写同一项目没有分布式锁。
- 视频任务能持久化 taskId，但没有重启恢复、503 退避和只重下载；媒体仍用固定文件名，重抽覆盖旧素材。
- 参考图编号和视频 content 仍是两套规则，尚未统一 material manifest；无台词在场人也未显式建模。
- 生产面板登记 job/ledger，但没有成本预估、指纹确认或失败自动重试。
- 删除项目后不会主动清会话绑定（UI 会回退到第一个项目；工具会提示重新打开）。
